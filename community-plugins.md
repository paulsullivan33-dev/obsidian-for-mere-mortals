# Community Plugins

Outcome: you can extend Obsidian with
other people's features while keeping
chapter 1's rule intact — knowing
what a plugin can do in principle,
what the gate is that you open, and
how to choose like someone lending a
house key, which is the act you are
performing.

This chapter is taught from the
documentation. The lab installed no
community plugin: its app had no
account and an intercepted network,
and the author considered that a
fitting state in which to write a
chapter whose whole content is *be
careful what you let in*. Nothing
below claims a run it did not have.

## What a community plugin is

A **community plugin** is a feature
written by somebody who is not the
maker — a calendar that understands
daily notes, a board that arranges
them, a bridge to another service —
published in the app's community
directory for anyone to install.
Plugins are programs, in the plain
sense: code that runs inside
Obsidian with the app's own reach.
That reach includes reading and
writing every file in your vault,
and reaching the network. There is
no sandbox and no permission list to
approve item by item. A plugin is
trusted the way a program you install
is trusted — wholly, or not at all.

## The gate: restricted mode

By default a vault is in **restricted
mode** (older versions call it safe
mode): community plugins cannot run
at all. Installing your first one
means switching restricted mode off
in settings, and the app makes you
do it deliberately, with the warning
written out. Read that warning as
the honest label it is: from that
moment, the vault's safety is the
sum of your choices. Plugins you
install live in `.obsidian/plugins/`,
one folder each — visible, countable,
removable. The census rule is the
same as chapter 12's: if you cannot
name what is in that folder, the
folder has grown beyond your audit,
and it is time to prune before you
add.

## Choosing like a key-lender

Five questions, in order, before any
install:

- **Whose is it?** A named author
  with a public history, or a
  stranger's weekend? Both have
  written fine plugins; only one has
  a reputation to lose.
- **Is it kept?** Recent releases,
  issues answered, a pulse. An
  abandoned plugin is a key cut for a
  lock that has since been changed —
  and Obsidian updates monthly.
- **How many keep it?** Download
  counts are not proof, but a plugin
  ten thousand diarists rely on has
  had ten thousand chances to be
  caught misbehaving.
- **What does it touch?** A plugin
  that reformats dates has no
  business with the network; one
  that syncs has no business without
  it. The description should make the
  reach sound proportionate to the
  job.
- **Can you leave?** The best plugins
  write *in your notes, in the open*
  — properties, plain text, ordinary
  files — so uninstalling loses a
  convenience, not your data. A
  plugin whose output only it can
  read is a landlord, not a tool.

And the standing rules afterwards:
few, famous, and audited. Update
deliberately, not automatically in
spirit. Remove what a month did not
use. Your notes are yours; keep the
list of other programs that can read
them short enough to recite.

Check, before any install, and
aloud: *whose program is this, what
can it reach, and what happens to my
notes the day it vanishes?* Three
comfortable answers is an install.
Two is a postponement. That is the
chapter; everything else is
catalogue.
