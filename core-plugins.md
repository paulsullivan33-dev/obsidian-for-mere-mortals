# Core Plugins

Outcome: you know which of Obsidian's
features are the app's own built-ins,
which thirty of them a new vault
carries, and which handful do the
daily work — because you have read
the list the app itself wrote.

## Built in, switched on or off

Obsidian's own features are **core
plugins**: thirty modules that ship
with the app, each switched on or off
per vault. The list lives in
`.obsidian/core-plugins.json`, and
the lab's copy is genuine — written
by the real app into the lab vault,
and parsed in transcript t06. On a
first opening, **twenty-one are on
and nine are off**, and the census
below is that file, not a brochure.

**On from the start.** File explorer;
search; the **quick switcher**;
graph; backlink; **canvas** (a
whiteboard whose boards are files of
JSON in the vault — another open
format hiding in plain sight);
outgoing links; the tag pane;
properties; page preview (hover a
link, see the note); daily notes;
templates; note composer (splitting
and merging notes with their links
kept); the command palette; the
status bar's editor readout;
bookmarks; outline (the note's
headings as a clickable map); word
count; **file recovery** (short-term
snapshots of edits, kept per user —
a net for fumbles, not a backup, as
chapter 17 insists); Sync (chapter
11's door, present but idle until
you pay and sign in); and **Bases**,
the newest arrival, given its
outline in chapter 14.

**Off until asked.** Footnotes;
slash commands; the unique-note
creator (notes named by timestamp,
for a particular capture-first way
of working); random note (a serendipity
button, and an honest one); slides
(notes as presentations); the audio
recorder; workspaces (saved layouts);
Publish (chapter 14's paid door);
and the web viewer.

## The handful that matter daily

Thirty switches sounds like
machinery; a day's real use touches
six. The explorer and the switcher
are how you *move* (chapter 8).
Search and backlinks are how you
*find* (chapters 6 and 8). Properties
is how facts stay facts (chapter 7).
Daily notes and templates are how the
notebook *continues* (chapter 9).
File recovery is how a bad Tuesday
stays a small one. The rest are
genuinely useful on their occasions —
the outline in a long note is a
small mercy — and harmless when
ignored, which is the correct
relationship with most settings.

Two working rules:

- **Switch on with a reason.** Each
  core plugin you enable adds a
  little interface and a little
  state. The defaults are the maker's
  own judgement about a new vault;
  depart from them one itch at a
  time.
- **The list is the truth.** When a
  feature seems missing, the question
  is never "which edition do I own" —
  it is whether its switch is on in
  this vault's `core-plugins.json`,
  a file you can now read with your
  own eyes (t06).

Check: open your vault's
`.obsidian/core-plugins.json` in a
text editor and count. Thirty names,
`true` or `false`, nothing else. A
program whose feature list is a file
you can read in the folder it serves
is a program that expects to be
audited — one of the better reasons
this guide can give for trusting it
with the diary, cautiously, per
chapter 1.
